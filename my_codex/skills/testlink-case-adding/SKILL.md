## Инструкция по выполнению
1. Пользователь должен указать на конкретный `.md`-файл с тест-кейсами. Если файла нет или Пользователь не указал файл - сообщить и завершить работу.
2. Взять креды доступа к `TestLink` из `.env`-файла.
3. Из `.md`-файла брать только тест-кейсы. Общее описание, требования и источники не учитывать при переносе.
4. Для каждого тест-кейса:
  - Брать конкретное наименование, без буквенно-числовой аббревиатуры;
  - Брать конкретные предусловия, если они имеются;
  - Брать шаги и ожидаемый результат.
5. Тест-кейс при переносе должен выглядеть следующим образом, вот полноценный пример:

Тест-кейс в `.md`:
```
### FFF-01. Успешная одиночная отправка списывает баланс.

Предусловия:
1. Клиент `prepaid = true`
2. Баланс клиента = `100`
3. Порог отключения = `0`
4. Цена одного сообщения = `10`
5. Маршрут и отправитель настроены корректно.

Шаги:

| Действие | Ожидаемый результат |
| :--- | :--- |
| Получить исходный баланс | Получен баланс |
| Отправить одиночное сообщение по `broker-api` | `broker-api` принимает запрос на отправку |
| Дождаться тарифицируемого статуса отправки | Сообщение получает ожидаемый статус |
| Проверить CDR/Детальную статистику | В CDR записана клиентская цена |
| Повторно проверить баланс | Баланс уменьшился на цену тарификации |

```

Соответственно, таким же образом тест-кейс должен быть заполнен в TestLink:
1. Наименование: Успешная одиночная отправка списывает баланс.
2. Условия: с заглавной буквы с переносом строки для каждого пункта, перечислить пункты из `Предусловия`.
3. Шаги: перенести шаги в том же порядке.
4. Приоритет - оставлять базовым для каждого тест-кейса.
